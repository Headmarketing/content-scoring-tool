# AI Content Audit Platform (v1)

A working, rule-based bulk content/SEO audit tool. No paid APIs — just
`requests`, `BeautifulSoup`, and `textstat`.

## What's implemented from the spec

- **Input:** sitemap URL, blog listing URL (fallback link-crawl), or CSV of URLs
- **Extraction:** metadata, headings, word count, reading time, paragraphs,
  lists, tables, FAQ detection, images/alt text, videos, internal/external
  links, schema.org types, breadcrumbs, Open Graph, author presence, dates
- **Scoring:** the exact 5-category weighted framework — Relevance 25%, SEO 20%,
  Quality 20%, Usefulness 25%, Readability 10% — all rule-based and explainable
  (see `scoring.py` for every rule)
- **Issue detection:** High/Medium/Low severity, grouped and counted site-wide
- **Recommendation engine:** priority-ranked, with % of site affected
- **Dashboard:** single self-contained HTML file (Chart.js), works by
  double-clicking — no server needed
- **Export:** CSV of the full content inventory

## Not included in this pass (flagged in the original spec as "Future" or as
infrastructure that doesn't fit a single script)

- Postgres / FastAPI / React / Docker service layer — this v1 is a CLI +
  static HTML report, which covers the actual audit workflow without needing
  you to stand up and maintain a server. Happy to build the full multi-user
  web-app version next if you want persistent history / multiple users hitting
  it from a browser.
- spaCy NLP — Relevance scoring uses transparent rule-based heuristics
  (title/H1 topic overlap, sub-heading coverage, FAQ presence) instead, to
  keep the tool dependency-light and fast. This can be upgraded to spaCy or a
  local LLM (Ollama) later without changing the scoring interface.
- Local LLM executive summaries, duplicate-content detection, historical
  tracking — listed as "Future Enhancements" in the spec, not v1.

## Setup

```bash
pip install -r requirements.txt
```

## Run it

```bash
# From a sitemap (recommended — most reliable discovery)
python main.py --sitemap https://yoursite.com/sitemap.xml

# From a blog listing page (crawls links if no sitemap exists)
python main.py --blog-url https://yoursite.com/blog

# From a CSV/text list of URLs (one per line, or first column)
python main.py --csv urls.csv

# Useful flags
python main.py --sitemap https://yoursite.com/sitemap.xml \
  --max-urls 200 --workers 8 --out-dir reports/ --site-label "Acme Blog"
```

Output lands in `reports/`:
- `content_health_dashboard.html` — open in any browser
- `content_inventory.csv` — every page with scores, for spreadsheets/BI

## Tuning the rules

Every scoring rule lives in `scoring.py` as plain Python (thresholds like
"word count < 800 → thin content"). Edit thresholds there to match your
editorial standards — no retraining, no black box.

## A working example is included

`demo_reports/content_health_dashboard.html` was generated by running this
exact tool against two sample pages (`sample_site/`) — one solid article,
one thin one — so you can see real scoring output before pointing it at your
own site.
